# Day 008｜LRU Cache 解題後檢討

> 建議先完成 `Day008LruCache.cs`、實際執行 xUnit 後再閱讀此檔與 `Day008LruCacheReference.cs`。

## 核心資料結構

使用 `Dictionary<int, LinkedListNode<(int Key, int Value)>>` 快速找到節點，搭配 `LinkedList` 的頭尾紀錄新舊使用順序：

- 最前端（First）= **最近使用**，最後端（Last）= **最久未使用**。
- `Get` 命中時把節點移到最前端；未命中回傳 `-1`，不能改變順序。
- `Put` 更新時修改 value 並把既有節點移到最前端，不可增加快取項目數。
- `Put` 新增且容量已滿時先刪除尾端（從 Dictionary 和 LinkedList 同步移除），再將新項目加入最前端。
- 容量 `0` 不能儲存項目；儲存值 `-1` 仍要被視為命中。

## 複雜度

| 操作 | 目標時間 | 說明 |
| --- | --- | --- |
| `Get` | 平均 **O(1)** | Dictionary 查節點 + LinkedList O(1) 移動 |
| `Put` | 平均 **O(1)** | 查詢／新增與尾端淘汰 |
| 空間 | **O(capacity)** | 一個 key 一個 dictionary 項目與鏈結串列節點 |

若使用 `List<T>.RemoveAt(0)`、每次查詢都 `ToList()`、每次操作都掃描所有 key、或為了找最舊 key 而排序，通常無法達到 O(1)。

## 易錯情況

- 成功 `Get` 卻未更新最近使用順序。
- 只更新既有 key 的值，卻忘記把它設為最近使用。
- `Get` 不存在時不應改動排序。
- 重複 `Put` 相同 key 不應增加容量。
- 容量為 0。
- `-1` 是有效 value，不要因為值為 -1 就當作未命中。
- LinkedList 的節點移動後，Dictionary 所指向的節點必須仍然有效。
