# Day 002 解法回顧（請先完成題目）

## 觀察

括號是否有效，和「總共有幾個開括號/閉括號」是兩件事。`([)]` 的數量各自相等，卻因為閉合順序錯誤而無效。

## 寫法比較

| 解法 | 時間複雜度 | 額外空間 | 評語 |
| --- | --- | --- | --- |
| 反覆以 `Replace("()", "")`、`Replace("[]", "")` 等方式刪掉配對 | 最壞約 O(n²) | 反覆配置字串 | 能理解但效率及可讀性較差 |
| `Stack<char>` 單趟走訪 | O(n) | O(n) 最壞情況 | 建議寫法：語意明確、易維護 |
| 固定長度陣列 / `Span<char>` 手動模擬堆疊 | O(n) | O(n) | 可減少配置；一般面試非必要，需注意 `stackalloc` 尺寸風險 |

## C# 程式碼品質建議

- 空輸入為 `true`；不合法字元一律 `false`；`null` 必須丟出 `ArgumentNullException`。
- 使用 `Stack<char>` 與 `switch` 或明確的 helper 判斷。使用 `Pop()` 前先檢查 `Count`，避免 `InvalidOperationException`。
- 若字串長度為奇數，可以立刻回傳 `false`（不是必須的最佳化）。
- `Stack<char>` 可使用 `TryPop`（在目標 Framework 支援時）簡化閉括號檢查。
- 注意不能只統計各括號數量，也不能忽略巢狀順序；測試 `([)]`、`)`、`(()`。
